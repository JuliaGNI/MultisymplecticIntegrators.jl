Example problems and diagnostics

The four example problems, each of which lives in its own submodule, and the diagnostics of a run.

MultisymplecticIntegrators.Wave — Module
Wave

The scalar wave equation ∂ₜ²u − c² ∂ₓ²u = 0 on x ∈ [0, l], with the standing-wave exact solution of the two lowest harmonics.

The Lagrangian density is L = ½v² − ½c²w², and the exact solution is

\[u(t, x) = (A₁\cos(πct/l) + B₁\sin(πct/l + π/6)) \sin(πx/l) + (A₂\cos(2πct/l) + B₂\sin(2πct/l + π/6)) \sin(2πx/l),\]

with v = ∂ₜu and w = ∂ₓu its derivatives.

problem = Wave.problem(timespan = (0.0, 3.0), timestep = 0.3, xstep = 0.01)

MultisymplecticIntegrators.VectorWave — Module
VectorWave

The wave equation for a field u ∈ ℝᴰ on x ∈ [0, l] with zero Dirichlet data, the density

\[L = \tfrac{1}{2}|u_t|^2 - \tfrac{c^2}{2}|u_x|^2 - \tfrac{m^2}{2}|u|^2 - \tfrac{\beta}{4}|u|^4,\]

the exact solution of the uncoupled case m = β = 0, each component a standing wave of Wave with amplitudes of its own, and the angular momentum J = ∫ (u₁ ∂ₜu₂ − u₂ ∂ₜu₁) dx of the D = 2 field.

L is invariant under a rotation of (u, v, w), so J is conserved; a numerical integration that loses it has lost the symmetry, which is the oracle of the vector case. The default parameters give the two components different phases, so that J is not zero.

problem = VectorWave.problem(timespan = (0.0, 1.0), timestep = 0.1, xstep = 0.05)

MultisymplecticIntegrators.VectorWave.VectorDensity — Type
VectorDensity(density, D = 2, β = 0)

The density of a component-major vector field u ∈ ℝᴰ: the scalar density summed over the D components, minus the quartic coupling ¼β|u|⁴. The scalar density carries no quartic term, so that the whole is invariant under a rotation of (u, v, w). u, v and w hold the D components' values at one point, in any indexable collection of length D: the couplings of the slab pass NTuple{D}s, and the energy diagnostics pass Vectors, or scalars where D = 1.

MultisymplecticIntegrators.SineGordon — Module
SineGordon

The nonlinear sine-Gordon equation c ∂ₜ²u − ∂ₓ²u = −sin(u) on x ∈ [0, l], with the exact solution of the travelling kink.

The Lagrangian density is L = ½(c v² − w²) + 1 + cos(u), and the exact solution is

\[u(t, x) = 4\arctan(\exp(γ (x - v t))), \qquad γ = 1 / \sqrt{1 - c v²},\]

with v = ∂ₜu and w = ∂ₓu its derivatives. γ is a function of c and the kink velocity, so the parameters are (c, velocity) and a kink exists only where c velocity² < 1.

problem = SineGordon.problem(timespan = (0.0, 10.0), timestep = 1.0, xstep = 0.01)

MultisymplecticIntegrators.LinearTransport — Module
LinearTransport

The linear transport equation ∂ₜu + c ∂ₓu = 0 on x ∈ [-0.5, 0.0], whose exact solution is the initial profile shifted by c t.

The Lagrangian density is the doubled field's, L = ψ (v₁ + c w₁) on D = 2: component 1 is the transported field u and component 2 the adjoint field ψ, which carries zero data. The variation in ψ gives the transport equation for u, and the variation in u the adjoint equation for ψ, so the density carries the dynamics that one field alone could not: it is linear in the velocities, its Legendre map is degenerate (p_u = ψ, p_ψ = 0), and the two components' rows carry each other's equation.

The exact solution of u is the Gaussian

\[u(t, x) = \frac{1}{2\sqrt{\pi}} \exp\!\big(-(x + 2 - ct)^2\big),\]

with v = ∂ₜu and w = ∂ₓu its derivatives, and the adjoint field's exact value is zero.

The transport equation needs its inflow value at x = -0.5, which WeakInitialAndBoundaryConditions imposes and CoefficientRestriction does not, so under the restriction the error is largest at that end and the converged order is read on x ≥ -0.5 + c t.

problem = LinearTransport.problem(timespan = (0.0, 10.0), timestep = 1.0, xstep = 0.01)

MultisymplecticIntegrators.Diagnostics — Module
MultisymplecticIntegrators.Diagnostics

Figures for the integrators of this package: a space-time plot of a solution, the energy error of several runs over time, an animation of the field, and the dispatcher that turns one archived run into the figure its kind asks for.

The methods are implemented in the MultisymplecticIntegratorsPlots extension, which loads together with Makie or a backend such as CairoMakie. The declarations here hold the API and its documentation, so that each name is documented whether or not a backend is loaded, and the extension documents no name a second time.

Why a submodule rather than three more exports

plot_solution and plot_energy_error are names GeometricProblems already exports — plot_solution from its problem submodules and plot_energy_error from its own Diagnostics. Exporting them from this package's top level would make them ambiguous in any scope that also does using GeometricProblems.Wave-style imports, which is what a script integrating a problem naturally writes. The extension therefore defines Diagnostics.plot_solution, which extends the declaration rather than shadowing a name, and a caller reaches it as MultisymplecticIntegrators.Diagnostics.plot_solution.

MultisymplecticIntegrators.Diagnostics.animate_solution — Function
animate_solution(problem, result; path, framerate = 15, title = nothing, figsize = nothing)

An animation of the field u(t, ·) over the stored steps of one run, written to path.

Only the first component of the field is animated, whatever the problem's dimension D.

result is what integrate returns and problem the problem it was integrated with. The frame at step n is the field on the problem's output grid, at the time of that step, so the animation shows the solution of the discrete problem and nothing interpolated between the steps.

Each frame's axis title shows the time of its step. title = nothing draws no heading before that time, as plot_solution draws none without an archive, and an empty string draws none either; a title is drawn before the time.

MultisymplecticIntegrators.Diagnostics.figures — Function
figures(data) -> Figure

The figure one archive earns: a "solution" archive draws as a space-time plot, a D-component solution as one panel per component, and an "energy" archive as the energy error of its series.

data is a run's archive as a plain dictionary — the schema is documented in scripts/README.md. Its "kind" selects the shape of figure, and a kind this module cannot draw is refused rather than guessed at: two figures drawn from the wrong keys look like a result.

This is what makes a renderer a dispatcher — glob a run directory, hand each archive over, save what comes back — rather than a second registry of which experiment produces which picture, kept in step with the first by hand. Naming the file is the caller's, from the archive's "stem": the figure does not know where output goes.

MultisymplecticIntegrators.Diagnostics.plot_energy_error — Function
plot_energy_error(times, errors; labels = nothing, path = nothing, title = nothing, figsize = nothing)
plot_energy_error(data::AbstractDict; kwargs...)

The relative energy error of several runs against time, on a logarithmic axis.

errors holds one series per run, in energy_error's units, and times either one time vector shared by every series or one per series. A zero error cannot be drawn on a logarithmic axis, so its point is dropped from both vectors rather than masked, which keeps the curve whole. A series with no drawable point is left out of the figure, and the legend names the series that were drawn: a legend over an empty axis claims a result that the figure does not show.

The dictionary form reads an archive whose "kind" is "energy".

Keyword arguments

  • labels = nothing: one legend entry per series.
  • path = nothing: write the figure there, as a PDF by its extension.
  • title = nothing, figsize = nothing: as for plot_solution; the form without an archive draws no heading.

MultisymplecticIntegrators.Diagnostics.plot_solution — Function
plot_solution(problem, result; path = nothing, title = nothing, figsize = nothing)
plot_solution(data::AbstractDict; kwargs...)

A space-time plot of one run: one heatmap panel per component of the field, the time axis running up the page and the problem's output grid across it, with the values read off the panel's colourbar.

result is what integrate returns, and problem the problem it was integrated with. The dictionary form reads the archive that scripts/archives.jl writes, whose "kind" is "solution".

Keyword arguments

  • path = nothing: write the figure there, as a PDF by its extension, beside returning it.
  • title = nothing: the heading across the figure. nothing draws the heading of the archive, which names the run and its time step, and the form without an archive draws none; an empty string draws none either, whatever the archive holds.
  • figsize = nothing: the size of the figure, in pixels, as (width, height).

MultisymplecticIntegrators.Diagnostics.plot_theme — Function
plot_theme()

The one theme of every figure of this package: the font sizes and weight, the line and marker sizes, and the colour cycle.

A function rather than a value, because a Makie Theme can only exist where Makie does, and this module is loaded whether or not a backend is. The extension defines it, and applies it inside each figure method, so that no method sets a font, a line width or a colour of its own: the attributes the theme names are the theme's in every figure, whatever ambient theme the caller set.
