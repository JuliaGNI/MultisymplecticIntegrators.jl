The problem types and the quadrature of the package, and the four example problems, each of which lives in its own submodule.

MultisymplecticIntegrators.AxisTabulation — Type
AxisTabulation{T}

The assembly tables of one axis of the tensor ansatz: at every point of the composite Gauss rule, the indices of the basis functions that are nonzero there and the values of those functions and of their first derivative, together with the nodes and the weights.

The tables are dense, q × width: a basis function of degree p is nonzero on p + 1 cells, so the support at one point is width functions wide (p + 1 away from an end, wider for a recombined basis, whose functions may reach further). An entry whose index is zero is padding and carries no term.

MultisymplecticIntegrators.CoefficientRestriction — Type
CoefficientRestriction() <: SlabCoupling

The coupling of two consecutive slabs by restriction: the top trace of the previous slab is restricted to the bottom constraints of the current one.

The bottom trace of a slab is its bottom row of coefficients, so the restriction is the row itself: the previous slab's top row is this slab's bottom datum, unchanged. The momentum flux goes with it. The v term of the interior weak form leaves one boundary term at the bottom of the slab, ∫ ∂L/∂v · φ dx at t̂ = 0, and the previous slab's top row of the weak form is exactly that load at its top — so the flux is not re-integrated from a trace but read off the row the previous slab already computed. At the first slab both come from the problem's initial condition.

The coupling adds no other term, because the interior weak form enforces everything else the slab needs.

source
MultisymplecticIntegrators.Continuation — Type
Continuation() <: SlabInitialGuess

The default initial guess: the previous slab's solution, carried into the new slab.

For the tensor B-spline ansatz under a CoefficientRestriction that is the previous slab's top coefficient row, repeated in every row: each row of the new slab starts where the previous slab ended. At the first slab there is nothing to carry, and the guess falls back to FitTo(InitialCondition()) with the ansatz's default fit method.

MultisymplecticIntegrators.CouplingData — Type
CouplingData

The coupling's block of the slab cache.

A coupling fixes how the free coefficients of a slab are laid out, adds terms to the residual, and may carry unknowns of its own between the coefficients and behind them. The block holds what it keeps between slabs — its datum, its unknowns, the tables its residual term evaluates and the scratch of that evaluation. It is built once, when the cache is built, and its type is a parameter of the cache, so that a coupling that keeps nothing pays for nothing.

MultisymplecticIntegrators.FitTo — Type
FitTo(target; method = nothing) <: SlabInitialGuess

Fit the ansatz to target on the slab, with the fit method method.

A target is evaluated on the slab — see InitialCondition, PreviousSlab, ExactSolution and TargetFunction — and the fit brings the ansatz to it. A method that is named is used as it is; an unnamed one resolves through default_fit(ansatz), so that an ansatz with a fit method of its own gets it.

target is a SlabTarget and method a SlabFitMethod; a value of another role, such as FitTo(Continuation()), has no method and is refused at construction.

A user-defined target is a subtype of SlabTarget with one method of

evaluate!(sample, target, cache, ansatz, problem, sol)

filling sample, of size (Qt, Qx, D), with the target's value at the quadrature points of the slab. The fit that follows takes sample from the cache, so a target that allocates nothing keeps the guess free of allocations.

MultisymplecticIntegrators.LagrangianDensity — Type
LagrangianDensity(L, u, v, w; params = NamedTuple())

The Lagrangian density L(u, v, w; params) of a field theory in one space dimension, where v = ∂ₜu and w = ∂ₓu, together with its three partial derivatives ∂u, ∂v and ∂w.

L, u, v and w are symbolic. Each of the four functions is built once by Symbolics.build_function(…; expression = Val(false)), so an evaluation is an ordinary Julia call and not a re-derivation of the expression. The names of params are the parameters of the density: every built function takes their values as further positional arguments.

Fields

  • L(u, v, w, p...): the density.
  • ∂u(u, v, w, p...), ∂v(u, v, w, p...), ∂w(u, v, w, p...): its partial derivatives.
  • names: the names of the parameters, in the order of the built functions' arguments.
  • params: the default parameter values.

Example

using Symbolics
@variables u v w
d = LagrangianDensity(v^2 / 2 - w^2 / 2, u, v, w; params = (c = 0.5,))
d(0.0, 1.0, 0.0, (c = 0.5,))   # the density, with the parameters named
d.∂v(0.0, 1.0, 0.0, 0.5)       # ∂L/∂v, with the values in argument order

MultisymplecticIntegrators.LagrangianPDEProblem — Type
LagrangianPDEProblem(density; D = 1, ics_function, bcs_function, exact_u, exact_v, exact_w,
                     timespan, timestep, xspan, xstep, params = density.params)

A Lagrangian field theory in one space dimension on a space-time slab, with a generic element type.

density is a Lagrangian density: a callable L(u, v, w, params) with a derivatives method returning its three partial derivatives ∂L/∂u, ∂L/∂v and ∂L/∂w. A LagrangianDensity supplies both for one component at a time; a density that couples the components of the field, such as the vector density that VectorWave.vector_density builds, supplies them for the D components of one point at once. The problem's parameters are the density's own params field where it has one, and the params keyword otherwise. ics_function(x, params) returns the named tuple (u = …, v = …, w = …) of the initial data on the vector x of grid points; each entry is a vector of length D * length(x), laid out component-major, θ = [θ¹; θ²; …], so that one scalar ansatz serves every component. bcs_function(times, params) returns the boundary data of the slab whose two times are times = (t₀, t₁): the exact values on the bottom and top traces, at the grid points of xspan and xstep, and at the two ends of xspan, at both times. exact_u, exact_v and exact_w are (t, x, params) functions, or nothing where the problem has no exact solution.

timespan, timestep, xspan and xstep are converted to the element type T of timespan. The functions of the problem take its parameters, never a module-level default.

problem = LagrangianPDEProblem(density;
    ics_function = (x, p) -> (u = …, v = …, w = …),
    bcs_function = (times, p) -> …,
    timespan = (0.0, 1.0), timestep = 0.1, xspan = (0.0, 1.0), xstep = 0.01)

MultisymplecticIntegrators.MultiplierCoupling — Type
MultiplierCoupling <: SlabCoupling

Abstract type of a coupling that imposes the slab's data weakly: the data is a row per multiplier function, the multiplier is an unknown of the step, and the momentum that leaves a slab is the multiplier the next slab enters with.

The unknown of the slab is the multiplier at its top surface, the momentum the slab hands on; the multiplier at its bottom surface is the datum, which the previous slab's top multiplier supplies.

MultisymplecticIntegrators.MultiplierData — Type
MultiplierData{ST} <: CouplingData

The block of a weak-multiplier coupling in the slab cache.

initial_multiplier is the datum of the step, the multiplier of the bottom surface, and top_multiplier its unknown, the multiplier of the top surface; top_values is the unknown at the nodes of the space quadrature, which is the momentum that leaves the slab. boundary_multiplier holds the 2 Nμ multipliers of the two ends of xspan — the first Nμ at x = a, the rest at x = b.

multiplier_basis and boundary_basis are the tables those multipliers are expanded in, at the nodes of the space and of the time quadrature. projection reads the bottom multiplier's datum back into its coefficients, and boundary_projection the momentum at the two ends of xspan; both are factorised once when the cache is built. target and boundary_target are the data of the step: the trace the initial condition is compared with, and the problem's side traces at each node of the time rule.

bottom_test and top_test are the test functions' values at the two ends of the time direction, and left_space, right_space, left_slope and right_slope those of the space functions and of their derivatives at the two ends of xspan. The remaining fields are the scratch of the residual, of the guess and of the boundary data, so that none of them allocates.

MultisymplecticIntegrators.PreviousSlab — Type
PreviousSlab() <: SlabTarget

The previous slab's solution, extrapolated in time beyond the top of that slab.

For the B-spline ansatz the extrapolation is the polynomial piece of the slab's top time cell, expanded about its top and evaluated at the displacement t̂ beyond it: a spline is a polynomial on each cell, so that piece extends the solution without inventing anything. At the first slab, where there is no previous solution, the target falls back to InitialCondition().

MultisymplecticIntegrators.Projection — Type
Projection() <: SlabFitMethod

The fit method of an ansatz that is linear in its coefficients: the L² projection of the target onto the slab's ansatz space, on the quadrature of the slab.

The projection solves the mass-matrix system of the ansatz, which SimpleSplines factorises once per quadrature rather than once per step. An ansatz whose coefficients enter a nonlinearity has no such system, and a Projection() on one is refused at construction — see SpaceTimeGalerkin.

A user-defined fit method is a subtype of SlabFitMethod, and places the coefficients of coeffs, of size (Nt, Nx, D), from the sampled target, in one method of

fit!(coeffs, method, ansatz, sample, cache)

cache is the SpaceTimeGalerkinCache, which owns the buffers a step reuses: a fit that allocates nothing works in them.

MultisymplecticIntegrators.SpaceTimeAnsatz — Type
SpaceTimeAnsatz

Abstract type of a space-time ansatz of one slab.

A slab is the space-time strip that one time step spans, [t_n, t_{n+1}] × xspan. The ansatz carries it in the normalised time coordinate t̂, where it is the rectangle [0, 1] × xspan.

An ansatz discretises the field u and its derivatives v = ∂ₜu and w = ∂ₓu on the slab, and gives the integrator the basis functions and the Jacobian from which it assembles the residual. It is not a method: a SpaceTimeMethod, such as SpaceTimeGalerkin, holds one.

source
MultisymplecticIntegrators.SpaceTimeGalerkin — Type
SpaceTimeGalerkin{A, C, G} <: SpaceTimeMethod

The space-time Galerkin slab integrator: a tensor B-spline ansatz A, a coupling C of consecutive slabs and an initial guess G.

The ansatz is a SpaceTimeAnsatz, the coupling a SlabCoupling and the guess a SlabInitialGuess — Continuation or FitTo. A value of another role, a method in the place of the ansatz or a target in the place of the guess, is refused when the method is built.

One step of the integrator solves one slab. The unknown is the coefficient array of the ansatz, (Nt, Nx) per component. A coupling that fixes the bottom row of the time direction supplies it as a datum — the initial condition at the first step and the previous slab's top row after it — and the remaining Nt - 1 rows are determined by the interior weak Euler–Lagrange form of the slab, tested against the basis functions that vanish at the top of the slab. The v term of that form leaves one boundary term at the bottom of the slab, the momentum flux, which the coupling supplies as well; the top of the slab is free, so its flux is not imposed but measured, and handed on as the next slab's bottom flux.

The unknown count is the coupling's: the free rows of each space function and each component, plus the coupling's own unknowns behind them. A CoefficientRestriction fixes the bottom row, so it leaves (Nt - 1) * Nx * D free coefficients; a weak-multiplier coupling imposes the initial condition with multipliers of its own, so all Nt rows are free and the multipliers follow them. A step is a nonlinear system of total_free_coefficients(method, problem) equations, which the ecosystem's Newton solver solves. The iterate count and the residual of every step are recorded in the cache, and the trace (u, v, w) at the top of the slab, at the nodes of the space quadrature, is kept for the diagnostics.

method = SpaceTimeGalerkin(
    TensorBSplineAnsatz(degree = 2, ncells = (1, 20), xspan = (0.0, 1.0)),
    CoefficientRestriction();
    initial_guess = Continuation())

result = integrate(problem, method)

MultisymplecticIntegrators.SpaceTimeGalerkinCache — Type
SpaceTimeGalerkinCache{ST, T, CD}

The cache of the slab integrator.

x is the nonlinear solver's vector: the free coefficients of the slab, laid out component-major with the time index fastest — the entry of free row a ∈ 1:Nf, space function j and component d is a + (j - 1) * Nf + (d - 1) * Nf * Nx, with Nf the coupling's free-row count — and then the coupling's own unknowns, in the layout of the coupling's block coupling, whose type is CD.

The data of a step are bottom and flux, the coupling's datum and its momentum load, and the results of the last step are top, the top row of the coefficient array, residual, the last weak form, and the trace at the top of the slab. iterations, residuals and initial_residuals record the Newton solve of every step: its iterate count, its final residual ‖F(x)‖₂ and its initial residual r₀ = ‖F(x₀)‖₂. steps counts the steps taken, which is what tells the coupling and the guess whether the slab is the run's first.

The buffers of a FitTo guess keep a step's guess from allocating: sample, of size (Qt, Qx, D), holds the target at the quadrature points; fit, of size (Nt, Nx, D), holds the fitted coefficients; initial_sample, of size (Qx, D), holds the problem's initial condition at the nodes of the space quadrature, evaluated once; and taylor holds the Taylor coefficients of the top time cell that PreviousSlab expands. weighted, load and fibre are the scratch of the Projection fit: the quadrature-weighted sample, its load in the time basis, and one space fibre of the coefficients.

MultisymplecticIntegrators.SpaceTimeQuadrature — Type
SpaceTimeQuadrature{T}

Composite Gauss–Legendre rule on one space-time slab.

The rule takes n Gauss–Legendre nodes per cell in each direction, placed between the breakpoints tbreaks of the normalised time coordinate t̂ ∈ [0, 1] and xbreaks of the physical space coordinate x. Because a cell's rule is exact for polynomials of degree 2n − 1, the composite rule integrates t̂ᵃ xᵇ exactly for a ≤ 2n − 1 and b ≤ 2n − 1 on any mesh, uniform or not.

The four boundary point sets of a slab are bottom and top, at t̂ = 0 and t̂ = 1 across the x nodes, and left and right, at the two ends of xspan across the t̂ nodes.

q = SpaceTimeQuadrature{Float64}(3; xbreaks = [0.0, 0.5, 1.0])
q((t, x) -> t^2 * x)     # the rule applied to a function of (t, x)

MultisymplecticIntegrators.TensorBSplineAnsatz — Type
TensorBSplineAnsatz(; degree, ncells, xspan, x_boundary = Dirichlet(), n = nothing)

A tensor B-spline ansatz of one space-time slab, on SimpleSplines.

The slab is the rectangle [0, 1] × xspan in the normalised time coordinate t̂ and the physical space coordinate x. The ansatz approximates the field by

\[u_h(t̂, x) = \sum_{i,j} \hat{u}_{ij} \, B_i(t̂) \, B_j(x),\]

with a clamped B-spline basis of degree degree[1] on ncells[1] uniform cells of [0, 1] and a B-spline basis of degree degree[2] on ncells[2] uniform cells of xspan. degree and ncells are given per direction, as a number for both or as a (time, space) tuple, so that the two directions may differ in degree and in cell count.

x_boundary is the boundary condition the space basis is built with: Dirichlet() recombines the basis at both ends of xspan, so that every function vanishes there, and Free() keeps the natural condition. The ansatz carries a homogeneous Dirichlet value in x only; an inhomogeneous value is a coupling's business.

n is the number of Gauss–Legendre nodes per cell in each direction, again a number or a (time, space) tuple; the default integrates the products of the basis functions and of their first derivatives exactly, which is p + 1 nodes for degree p, the count the products of the basis functions need.

Both degrees are at least 1. The slab core reads the space gradient ∂ₓu from the same space basis, and a piecewise-constant degree-0 basis carries none, so a lower degree raises ArgumentError.

The ansatz counts the degree, which is what SimpleSplines takes; a basis of order k is one of degree k - 1.

ansatz = TensorBSplineAnsatz(degree = 2, ncells = (1, 20), xspan = (0.0, 1.0))

MultisymplecticIntegrators.WeakInitialAndBoundaryConditions — Type
WeakInitialAndBoundaryConditions(; multiplier_basis = :bspline) <: SlabCoupling

The initial condition and the space boundary conditions of a slab, imposed weakly.

The initial condition is imposed as WeakInitialCondition imposes it. The multipliers at x = a and at x = b are unknowns of the step as well, and their rows are

\[\int \bigl( g_a(t) - u(t, a) \bigr) \, \chi_p(t) \, dt , \qquad \int \bigl( g_b(t) - u(t, b) \bigr) \, \chi_p(t) \, dt ,\]

where g_a and g_b are the problem's side traces, evaluated at each node of the time trace, so that inhomogeneous data is imposed as it stands. The multiplier basis is the ansatz's own trace basis, or the nodal basis of that same set of functions, so that a slab with Nt time functions and Nx space functions has Nx - 2 multipliers at the bottom surface, without its two corner functions, and Nt at each end of xspan.

The boundary rows carry an unknown, so the ansatz must take x_boundary = Free(); every other value throws an ArgumentError naming the condition the coupling needs and the one it got. A Dirichlet() basis in particular makes the trace vanish at each end of xspan, which would leave the rows empty.

method = SpaceTimeGalerkin(
    TensorBSplineAnsatz(degree = 2, ncells = (2, 20), xspan = (0, 1),
        x_boundary = Free()),
    WeakInitialAndBoundaryConditions())

MultisymplecticIntegrators.WeakInitialCondition — Type
WeakInitialCondition() <: SlabCoupling
WeakInitialCondition(; multiplier_basis = :bspline) <: SlabCoupling

The initial condition of a slab, imposed weakly.

The bottom row of the coefficient array is free, so all Nt rows of the slab are unknowns, and the slab is closed by one row per multiplier function ψ_p,

\[\int \bigl( u_0(x) - u(0, x) \bigr) \, \psi_p(x) \, dx ,\]

where u₀ is the problem's initial condition on the first slab and the previous slab's top trace on every later one. The multiplier at the bottom surface enters the momentum balance as the momentum that enters the slab: the least-squares fit of ∂L/∂v(u₀, v₀, w₀) on the first slab, and the previous slab's top multiplier afterwards.

multiplier_basis names the basis of ψ_p: :bspline, the ansatz's own trace basis, or :lagrange, the nodal basis of that same set of functions.

The coupling imposes no space boundary condition, so the ends of xspan are left to the space basis: the ansatz must take x_boundary = Dirichlet(), and every other value throws an ArgumentError that names the condition the coupling needs and the one it got. A Free() basis leaves the ends unconstrained, and the remaining conditions constrain them in a way the interior weak form does not carry.

method = SpaceTimeGalerkin(
    TensorBSplineAnsatz(degree = 2, ncells = (2, 20), xspan = (0, 1)),
    WeakInitialCondition())

GeometricBase.integrate — Method
integrate(problem::LagrangianPDEProblem, method::SpaceTimeMethod; kwargs...)
integrate(integrator::GeometricIntegrator)

Integrate problem with method and return the named tuple (; solution, traces).

solution is the GeometricSolution on the output grid, and traces holds one entry per stored step: the top trace (u, v, w) of that step at the nodes of the space quadrature, as the method's top_trace gives it, or nothing where the method keeps none. The trace is needed at the quadrature nodes rather than the interior ones because the energy diagnostics integrate it there, at the accuracy of the Gauss rule.

The steps are driven one at a time, because the trace of a step exists only while its cache does. Every call starts a new run: the integrator's cache is reset first, so its first slab takes the problem's initial data and the steps it records belong to this run alone. As in the ecosystem's integrate!, a step whose state holds a NaN ends the run with a warning; traces then ends at that step, and the solution holds the NaN there. A step whose nonlinear solve raises a NonlinearSolverException ends the run with a warning too; traces then ends at the step before it, and the solution is valid up to that step only. The keyword arguments go to the integrator's constructor, and to nothing else.

Refuse every space basis but a Dirichlet() one, naming the condition the coupling needs and the one the ansatz has: the coupling imposes the initial condition alone, so the basis itself must constrain the two ends of xspan. A Free() basis leaves them unconstrained, and every other condition constrains them in a way that the interior weak form does not carry.

source
MultisymplecticIntegrators.check_method — Method
check_method(problem, method)

Reject a method that the problem cannot support, before any step runs.

The refusals are ArgumentErrors: a target that reads the exact solution of a problem that has none, a fit that needs an ansatz linear in its coefficients on one that is not, an ansatz of another element type than the problem's, and an ansatz on another space interval than the problem's. The last two name the two values they compared, and the element type is compared first, so a pair that mismatches in both hears about the type.

MultisymplecticIntegrators.interior_weak_form! — Method
interior_weak_form!(residual, ∂u, ∂v, ∂w, tabulation, h)

The interior weak Euler–Lagrange form of one slab, from the derivatives of the density at the quadrature points.

For a test function φ it reads

\[\int_0^1 \!\! \int_{x_{\min}}^{x_{\max}} \Bigl( h \, \frac{\partial L}{\partial u} \, \phi + \frac{\partial L}{\partial v} \, \partial_{\hat t} \phi + h \, \frac{\partial L}{\partial w} \, \partial_x \phi \Bigr) \, dx \, d\hat t ,\]

which is the variation of the action \int \int L \, dt \, dx with the derivatives left on the test function, dt = h \, d\hat t. The one factor of h that the v term does not carry is the 1 / h of ∂ₜu = ∂_{t̂}u / h, so the three terms are the three of δS with no factor dropped. The residual is that form for every basis function, in the coefficient layout of the slab.

MultisymplecticIntegrators.least_squares — Method
least_squares(basis, weights)

The operator that reads a trace given at the nodes back into the coefficients of basis, by the quadrature-weighted L² projection (B W Bᵀ)⁻¹ (B W) of m: the coefficients c that minimise Σᵣ ωᵣ (Σₚ cₚ Bₚᵣ - mᵣ)², with W the rule's weights, so that ∫ c(x) ψ_p(x) dx = ∫ m(x) ψ_p(x) dx for every function of basis.

The mass matrix is factored once, here, and the operator is reused by every step. An unweighted nodal fit of the same values is not this projection: a basis that no longer reproduces the trace, such as one whose corner functions have left, reads the momentum of the datum wrongly, because the fit minimises the residual at the nodes alone.

MultisymplecticIntegrators.slab_bottom! — Method
slab_bottom!(cache, coupling, problem, ansatz, sol)

Fix the data of the slab: the trace the initial condition is compared with — the problem's initial condition on the first slab, the previous slab's top trace afterwards — and the problem's side traces at each node of the time rule.

The multiplier of the bottom surface is a datum of the step as well, and this function fixes it with the trace: on the first slab it is the momentum of the problem's initial data, ∂L/∂v(u₀, v₀, w₀), read into the multiplier basis, and afterwards the multiplier the previous slab solved at its top surface. MultisymplecticIntegrators.VectorWave — Module
VectorWave

The wave equation for a field u ∈ ℝᴰ on x ∈ [0, l] with zero Dirichlet data, the density

\[L = \tfrac{1}{2}|u_t|^2 - \tfrac{c^2}{2}|u_x|^2 - \tfrac{m^2}{2}|u|^2 - \tfrac{\beta}{4}|u|^4,\]

the exact solution of the uncoupled case m = β = 0, each component a standing wave of Wave with amplitudes of its own, and the angular momentum J = ∫ (u₁ ∂ₜu₂ − u₂ ∂ₜu₁) dx of the D = 2 field.

L is invariant under a rotation of (u, v, w), so J is conserved; a numerical integration that loses it has lost the symmetry, which is the oracle of the vector case. The default parameters give the two components different phases, so that J is not zero.

The nonlinear sine-Gordon equation c ∂ₜ²u − ∂ₓ²u = −sin(u) on x ∈ [0, l], with the exact solution of the travelling kink.

MultisymplecticIntegrators.LinearTransport — Module
LinearTransport

The linear transport equation ∂ₜu + c ∂ₓu = 0 on x ∈ [-0.5, 0.0], whose exact solution is the initial profile shifted by c t.

The Lagrangian density is L = ½u (v + c w). It is a null Lagrangian: its Euler–Lagrange expression vanishes identically, because ∂L/∂u = (v + c w)/2, ∂ₜ(∂L/∂v) = ∂ₜu/2 and ∂ₓ(∂L/∂w) = c ∂ₓu/2. The transport equation is therefore carried by the constraint v = −c w, which the ansatz of the family that integrates this problem imposes, and not by the density alone. The exact solution is the Gaussian

\[u(t, x) = \frac{1}{2\sqrt{\pi}} \exp\!\big(-(x + 2 - ct)^2\big),\]
